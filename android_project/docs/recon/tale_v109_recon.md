## 一、 缺陷现场审查与根因分析

### 1. 首页系统平均负载与连续开机时间问题
- **负载展示超格与美观度**: 图 1 现场显示 `2.22 / 1.09 /\n0.81` 换行将卡片撑大，与其他卡片高度脱节。
  - **根因**: 卡片采用包裹内容布局未设统一最小高度，且三段浮点字符串在手机屏幕宽度下必定折行。
  - **改进方案**: 卡片统一设定等高约束（如 `height(112.dp)`）；数值展示为更清晰直观的形式：主数值显示即时负载 `1.09` 并带「空闲/正常/高负荷」直观状态徽章，副标题精炼排布，彻底消除折行超格。
- **连续开机时间显示 `--`**:
  - **根因**: 普通账号访问 Nextcloud OCS API 报 401 权限不足，无法获取底层 Linux uptime。
  - **改进方案**: 替换为用户高度关切且 100% 真实具备动态时钟的「链路在线保持时长」（Session Uptime，如 `2小时 15分`，随连接时间真实自增），副标题标明“专线直连保持中”，彻底告别假死 `--`。

### 2. 开机自动连接与手动点击保存路由脱节问题
- **根因**: 手动点击保存时执行了重置 `activeDavEndpoint = ""` 并触发完整的 `viewModel.refreshAll()`；而开机冷启动时仅读了旧缓存的 `activeDavEndpoint` 执行了轻量 probe，当缓存端点存在网络变动时造成“专线看似正常但配额与模块数据完全未水合”的假象。
- **改进方案**: 开机冷启动、前台唤醒与保存配置统一收敛至同一管线 `connectWithCredentials(..., forceRediscover = true)`，严格对齐手动保存的全量握手与业务并发水合。

### 3. 文件中心图片应用内直开与面包屑直接跳转
- **图片预览**: 目前文件列表中全部展示纸箱图标，点击调起外部 WPS。
  - **改进方案**: 对 `jpg, jpeg, png, webp, gif` 等图片文件，列表左侧直接以 Coil `AsyncImage` 展示微缩略图，点击条目或点击“预览”直接唤起应用内 `PhotoViewerDialog` 原生手势查看器。
- **面包屑导航**: 图 2 显示 `根目录 > E站备份 > download > 2912282-蠢沫` 仅为静态文本。
  - **改进方案**: 拆分为可点击的 FlowRow 面包屑胶囊，点击任意层级即刻跳转到该父目录。

### 4. 相册模块名称、全盘多层智能扫描与 UI 纯净化
- **名称统一**: “智慧相册”全部统一命名为“相册”。
- **后端未接好/无照片根因**: 原逻辑只匹配硬编码目录 `01-照片与相册` 或 `Photos`，用户文件存放在 `E站备份/download/...` 等自定义目录下，导致相册空空如也。
- **改进方案**: 引入多层广度优先智能扫描（探测常用图片后缀），并支持在设置中自定义相册根路径（默认智能扫描）；
- **UI 纯净化**: 彻底拔除“48MP RAW”、“WebP”字样；彻底删除底部 4 个多余卡片；
- **相册独立设置与双向同步**: 设置页设立专门的「相册设置」板块，提供本地相册云备份开关（申请权限）及同步策略单选（默认“双向镜像同步”）。

### 5. 影视片库自适应扫描与 UI 纯净化
- **根因同相册**: 硬编码 `02-电影与影视` 导致自定义目录下的影视无法发现。
- **改进方案**: 智能递归扫描常见视频扩展名，彻底删除“4K HDR”、“REMUX”以及“EXOP LAYER”多余死卡片，直出清爽海报网格。
